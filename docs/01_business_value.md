# 01. 사업 가치 설계

## 1. 핵심 명제

플로머스의 가장 큰 사업적 가치는 직접 상품을 파는 것보다 **제조사·유통사·판매사 사이의 적합한 조합을 찾아 거래를 만들어주는 것**에 있다.

```text
직접 판매 = 상품 1개를 팔아 마진을 얻는 구조
매칭 인프라 = 거래가 발생할 조합을 만들고 반복 거래를 설계하는 구조
```

상품판매는 초기 학습과 현장 데이터 확보를 위한 실험실이다. 최종 자산은 다음 네 가지다.

```text
업체 DB
상품/스펙 DB
플랫폼·트렌드 반응 데이터
실제 거래 결과 데이터
```

---

## 2. 고객별 핵심 문제

### 제조사

```text
좋은 제품은 있으나 판로가 약하다.
어느 국가·채널에 맞는지 판단하기 어렵다.
유통사와 판매사를 직접 찾기 어렵다.
샘플, MOQ, 인증, 상세페이지, 통관, CS를 혼자 처리하기 어렵다.
```

### 유통사

```text
팔 상품은 필요하지만 검증된 제조사를 찾기 어렵다.
마진·MOQ·납기·클레임 조건을 비교하기 어렵다.
위치와 물류 역량에 맞는 상품을 선별해야 한다.
```

### 판매사

```text
콘텐츠와 판매력은 있으나 안정적인 상품 공급처가 부족하다.
트렌드에 맞는 상품을 계속 찾아야 한다.
위탁/사입 조건, 반품 책임, 상세페이지 소재가 필요하다.
```

---

## 3. 플로머스의 가치 사슬

```text
데이터 수집
→ 제품·포트폴리오·트렌드 구조화
→ 지식 그래프 구축
→ 맥락 기반 검색
→ 제조사·유통사·판매사 조합 추천
→ 30일 테스트 거래
→ 본계약/재발주
→ 거래 결과 데이터 반영
```

---

## 4. 수익 모델

| 단계 | 상품 | 수익 방식 |
|---|---|---|
| 1 | 판로 진단 리포트 | 건당 진단비 |
| 2 | 매칭 후보 리포트 | 후보 추천비 / 미팅 수수료 |
| 3 | 30일 테스트 판매 패키지 | 운영비 / 콘텐츠비 / KOC비 |
| 4 | 본계약 연결 | 성사 수수료 |
| 5 | 반복 거래 운영 | 거래액 수수료 / 정산 관리비 |
| 6 | 데이터 구독 | 월 구독료 |
| 7 | SI/SaaS | 구축비 / 사용료 |

---

## 5. 핵심 원칙

```text
소개만 하면 브로커다.
검증된 조합을 만들면 플랫폼이다.
반복 거래를 관리하면 인프라다.
거래 결과 데이터를 축적하면 해자가 된다.
```
