# 11. 고도화 분석 프레임워크

## 1. 분석의 중심 명제

플로머스의 데이터 전략은 “많이 수집하는 것”이 아니라 **거래 성사 가능성을 설명하고 높이는 것**이다. 따라서 모든 데이터는 아래 질문에 답해야 한다.

```text
이 제조사의 이 제품은
어느 국가에서,
어떤 유통사를 거쳐,
어떤 판매사가,
어떤 트렌드 문장으로 팔 때
거래가 성사될 가능성이 가장 높은가?
```

이 질문을 기준으로 데이터는 4개 층으로 나뉜다.

| 층 | 목적 | 대표 데이터 | 가치 |
|---|---|---|---|
| 관찰 데이터 | 후보를 넓게 찾음 | 웹페이지, 공공 API, 플랫폼 랭킹 | 리드 발굴 |
| 해석 데이터 | 판매 맥락을 붙임 | 카테고리, 트렌드, 가격대, 포트폴리오 | 매칭 판단 |
| 검증 데이터 | 실제 가능성을 확인 | 샘플, 미팅, KOC 테스트, 30일 판매 | 실패 위험 축소 |
| 반복 데이터 | 해자를 만듦 | 재발주, 계약, 정산, 클레임, 장기 성과 | 추천 정확도 향상 |

---

## 2. 플로머스 가치 루프

```text
외부 데이터 수집
→ 후보 업체/상품 추출
→ LLM Wiki와 지식 그래프 구성
→ 맥락 검색으로 조합 추천
→ 30일 테스트 거래
→ 결과 데이터 입력
→ 매칭 점수 보정
→ 더 좋은 조합 추천
```

이 루프가 10회만 돌아도 “감”이 쌓이고, 100회가 넘으면 카테고리별 패턴이 보이며, 500회 이상부터는 외부에서 복제하기 어려운 거래 데이터 자산이 생긴다.

## 3. 분석 축

### 3.1 제조사 분석 축

제조사는 회사가 아니라 **제품 단위**로 분석한다.

```text
제품 상세페이지
스펙
인증
성분/소재
패키지
MOQ
리드타임
OEM/ODM 가능성
수출 경험
응답 속도
```

분석 질문:

```text
제품이 콘텐츠화 가능한가?
국가별 인증 리스크가 있는가?
소량 테스트가 가능한가?
패키지 현지화가 가능한가?
재구매형인가, 선물형인가, 충동구매형인가?
```

### 3.2 유통사 분석 축

유통사는 **포트폴리오와 위치**로 분석한다.

```text
취급 브랜드
취급 카테고리
창고/지사 위치
통관·물류 가능성
사입/위탁/총판 거래 방식
온라인/오프라인 채널
```

분석 질문:

```text
이 유통사는 어느 지역을 커버할 수 있는가?
소량 테스트형인가, 대량 총판형인가?
물류는 강하지만 콘텐츠 판매는 약한가?
어떤 판매사와 붙어야 보완되는가?
```

### 3.3 판매사 분석 축

판매사는 **포트폴리오와 트렌드 적합성**으로 분석한다.

```text
베스트셀러
가격대
리뷰 키워드
콘텐츠 스타일
팔로워/반응
고객층
채널
광고/라이브 역량
```

분석 질문:

```text
이 판매사는 어떤 욕망을 팔 수 있는가?
가격대가 제조사 상품과 맞는가?
콘텐츠형인가, 검색형인가, 라이브형인가?
위탁이 가능한가, 사입만 가능한가?
```

## 4. 조합 분석

개별 업체 점수가 높아도 조합이 안 맞으면 거래는 깨진다. 플로머스의 분석 단위는 다음이어야 한다.

```text
제조사 × 제품 × 유통사 × 판매사 × 국가 × 채널 × 트렌드
```

조합 판단 항목:

| 항목 | 질문 |
|---|---|
| 제품-국가 적합도 | 이 제품이 해당 국가 소비자 욕망과 맞는가? |
| 제품-채널 적합도 | 이 제품이 검색형/콘텐츠형/라이브형 중 어디에 맞는가? |
| 제조-유통 적합도 | MOQ, 납기, 인증, 물류 조건이 맞는가? |
| 유통-판매 적합도 | 유통사가 판매사의 주문·반품·배송을 받쳐줄 수 있는가? |
| 판매-트렌드 적합도 | 판매사의 포트폴리오가 현재 트렌드와 맞는가? |
| 경제성 | 공급가, 판매가, 수수료, 물류비 후 마진이 남는가? |
| 실행성 | 30일 안에 샘플/상세/판매 테스트가 가능한가? |
| 리스크 | 인증, IP, 통관, 반품, 플랫폼 정책 리스크는 무엇인가? |

---

## 5. 분석 결과물

플로머스 분석은 반드시 “결론 카드”로 끝나야 한다.

```text
1. 추천 조합
2. 추천 근거
3. 리스크
4. 필요한 추가 확인 데이터
5. 30일 테스트 설계
6. 본계약 판단 기준
```

정보를 보여주는 데서 끝나면 리포트 회사다. 다음 액션까지 설계하면 거래 운영사가 된다.

---

## 6. 데이터 성숙도 단계

| 단계 | 상태 | 가능한 상품 |
|---|---|---|
| Level 0 | 엑셀 명단 | 리드 리스트 |
| Level 1 | 업체/상품 위키 | 판로 진단 리포트 |
| Level 2 | 지식 그래프 | 조합 추천 |
| Level 3 | 테스트 거래 결과 축적 | 30일 검증 패키지 |
| Level 4 | 반복 거래/재발주 데이터 | 거래 수수료, 운영 대행 |
| Level 5 | 추천 정확도 자동 보정 | SaaS, 데이터 구독, SI |

---

## 7. 최종 판단

플로머스가 수집하는 데이터는 “시장 리서치 자료”가 아니라 **거래 판단의 기억**이다. 시간이 지날수록 플로머스가 알아야 하는 것은 다음이다.

```text
어떤 업체가 약속을 지키는가?
어떤 상품이 어느 채널에서 전환되는가?
어떤 조건에서 거래가 깨지는가?
어떤 조합이 재발주까지 이어지는가?
```

이 데이터가 쌓일수록 플로머스는 업체 소개자가 아니라 **거래 성사 확률을 높이는 지식 기반 매칭 인프라**가 된다.
