# 10. 지금까지 논의 요약

## 1. 사업 방향

플로머스는 단순 쇼핑몰이나 상품 판매사가 아니라, 한·중·일 제조사·유통사·판매사를 연결하는 **검증형 B2B 커머스 매칭 인프라**로 설계한다.

```text
제조사는 맞는 판로를 찾고,
유통사는 맞는 상품을 찾고,
판매사는 팔릴 상품을 찾고,
플로머스는 거래 가능성이 높은 조합을 설계한다.
```

---

## 2. 직접 판매의 역할

직접 상품 판매는 최종 목적이 아니라 학습 수단이다.

```text
직접 판매
→ 시장 반응 확인
→ 상품·가격·리뷰·반품 데이터 확보
→ 매칭 점수 개선
→ 검증된 조합 추천
```

---

## 3. 데이터 전략

수집할 데이터는 세 주체별로 다르게 본다.

```text
제조사:
홈페이지 제품 상세페이지와 스펙 중심

유통사:
포트폴리오, 위치, 물류, 채널 중심

판매사:
포트폴리오, 판매 채널, 콘텐츠 스타일, 트렌드 중심
```

시장 데이터와 플랫폼 데이터는 방향을 잡는 데 쓰고, 플로머스 자체 거래 데이터는 핵심 해자로 삼는다.

---

## 4. LLM Wiki / 지식망 구상

일반 DB가 아니라 연결성 기반 지식망을 만든다.

```text
Manufacturer
→ Product
→ ProductSpec
→ Trend
→ Distributor
→ Location
→ Seller
→ Channel
→ Transaction
```

검색은 업체명 찾기가 아니라 거래 가능성 탐색이다.

---

## 5. 검색 결과의 최종 모습

검색 결과는 리스트가 아니라 조합 카드여야 한다.

```text
제조사 × 제품 × 유통사 × 판매사
+ 대상 국가
+ 대상 채널
+ 매칭 점수
+ 추천 근거
+ 리스크
+ 다음 액션
```

---

## 6. MVP 우선순위

초기 범위는 좁게 잡는다.

```text
국가:
한국 → 일본
한국 → 중국

카테고리:
헤어·향
K-뷰티
소형 생활용품

초기 데이터:
제조사 100개
제품 500개
유통사 100개
판매사 100개
트렌드 키워드 300개
테스트 거래 10개
```

---

## 7. 최종 비전

플로머스는 데이터 자체를 파는 회사가 아니라, 데이터로 거래를 만들어내는 회사가 되어야 한다.

```text
공개 데이터는 입구다.
플랫폼 반응 데이터는 방향이다.
직접 테스트 거래 데이터는 자산이다.
반복 거래 데이터는 해자다.
```
