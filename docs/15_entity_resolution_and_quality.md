# 15. 엔티티 정규화와 데이터 품질

## 1. 왜 중요한가

맥락 검색의 품질은 LLM보다 데이터 정규화에 더 많이 좌우된다. 같은 업체가 여러 이름으로 저장되면 그래프가 깨진다.

```text
ABC코스메틱
ABC Cosmetics
에이비씨코스메틱
ABC COSMETIC CO., LTD.
```

위 네 개가 같은 업체인지 판단하지 못하면 거래 이력과 신뢰도가 분산된다.

---

```text
주소
키워드
트렌드명
```

---

## 3. 회사 엔티티 정규화

우선순위:

```text
1. 사업자등록번호 / 법인번호 / 통일사회신용코드
2. 공식 도메인
3. 법인명 정규화
4. 주소 유사도
5. 대표자/전화번호/이메일
6. 브랜드/제품 포트폴리오 일치도
```

정규화 결과:

```json
{
  "canonical_company_id": "company_abc_cosmetics_kr",
  "aliases": ["ABC코스메틱", "ABC Cosmetics", "에이비씨코스메틱"],
  "identifiers": {
    "business_registration_number": "...",
    "domain": "abc.example.com"
  },
  "confidence": 0.92
}
```

---

## 4. 제품 엔티티 정규화

제품은 이름이 자주 바뀌므로 스펙 기반 정규화가 필요하다.

```text
제품명
브랜드
용량/중량
패키지
성분/소재
이미지 해시
바코드/GTIN
카테고리
```

---

## 5. 카테고리 표준화

외부 소스마다 카테고리 체계가 다르다.

```text
Rakuten genre
Naver shopping category
Amazon browse node
HS code
내부 Flomers category
```

내부 카테고리를 중심으로 매핑한다.

```yaml
haircare:
  aliases:
    - 헤어케어
    - ヘアケア
    - hair oil
    - hair treatment
  hs_code_candidates:
    - "3305"
```

---

## 6. 데이터 품질 점수

```text
품질 점수 =
필수 필드 완성도
+ 출처 신뢰도
+ 최신성
+ 중복 제거 확신도
+ 검증 수준
- 충돌 데이터 패널티
```

예시:

| 항목 | 배점 |
|---|---:|
| 필수 필드 완성도 | 25 |
| 출처 신뢰도 | 25 |
| 최신성 | 20 |
| 엔티티 매칭 확신도 | 15 |
| 운영자 검수 | 15 |
| 충돌 패널티 | -20 |

---

## 7. 충돌 데이터 처리

동일 필드에 다른 값이 들어오면 최신값을 무조건 쓰면 안 된다.

```text
정부 API > 업체 제출 자료 > 공식 홈페이지 > 플랫폼 공개 페이지 > 일반 웹페이지
```

단, 제품 상세와 포트폴리오처럼 공식 홈페이지가 가장 최신일 수 있는 항목은 예외 규칙을 둔다.

---

## 8. 최신성 정책

| 데이터 | 유효 기간 |
|---|---:|
| 판매사 베스트셀러 | 7~14일 |
| 리뷰/댓글 키워드 | 14~30일 |
| 제품 상세페이지 | 30~90일 |
| 유통사 포트폴리오 | 60~120일 |
| 사업자 상태 | 30일 |
| 인증/리콜 | 7~30일 |
| 거래 결과 | 영구 보존, 최신 가중치 우선 |

---

## 9. 운영자 검수 큐

자동 수집 후 바로 추천에 쓰지 말고, 중요한 필드는 검수 큐에 올린다.

```text
신규 제조사
신규 유통사
신규 판매사
신뢰도 낮은 고점수 조합
리스크 감점이 큰 조합
거래 성사 가능성이 높은 조합
```

검수 결과:

```text
승인
조건부 승인
보류
차단
중복 병합
```

---

## 10. 핵심 원칙

```text
많은 데이터보다 신뢰 가능한 연결이 중요하다.
정규화되지 않은 데이터는 그래프를 망친다.
거래 결과로 검증된 데이터는 가장 높은 가중치를 가진다.
```
